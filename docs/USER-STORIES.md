CSC 530 Senior Capstone Project Idea - COBIS

Overview & Background

The College of Business Information System (COBIS) is a tool that allows faculty, department chairs, and administrators to query information about classes, students, rosters, and faculty.
A replacement for the COBIS application is needed, as the current system is not user-friendly. It is essential that the new application prioritize usability and accessibility.

The existing application is built in Microsoft Access and interacts with a SQL Server database. It is currently deployed as a .accdb file, but this implementation and deployment method are neither efficient nor suitable for long-term use.

There is no specific preference regarding the programming language or technology stack for the new application. However, a web-based frontend that utilizes Murray State's SSO authentication is likely to be a suitable solution.

UX Philosophy

The current design philosophy for the application involves creating a specific stored procedure for each type of report. However, a different approach is desired for the new application. The new system should be flexible and amenable to a wide variety of queries and reports.

The goal is to develop a user-friendly tool that enables users to query the database and filter and sort information in an open-ended manner. Rather than relying on predefined reports, the tool should provide a frontend interface that allows users to generate custom queries, apply filters, and sort data dynamically. Additionally, the system should ensure that data access is restricted based on user roles, maintaining security and appropriate permissions.

User Roles

Faculty. Faculty should be able to access all information about their own courses.

Advisors. Advisors should be able to access all information about their advisees.

Program Coordinators. Program coordinators should be able to access all information about students and faculty within their programs.

Department Chairs. Department chairs should be able to access all information about students and faculty within their department.

Administrators/Administrative Assistants. Admins should be able to see information about students and faculty within their departments or areas, but should NOT have access to FERPA protected info. For example, they should be able to see course rosters and enrollment numbers, but they should not be able to see individual student grades.

Note: User roles are NOT mutually exclusive. For example, advisors can also be faculty, and department chairs can also be faculty and advisors.

User Stories

The following is a list of specific use cases. However, the tool should not be designed— as it currently is— to be limited to these predefined use cases. Instead, it should be flexible and adaptable to various user needs.

If a user needs to retrieve information that is not explicitly covered by one of the predefined use cases, the tool should be capable of accommodating such queries. The primary function of the tool should be to provide a frontend interface to the database that allows users to query, filter, and sort data, while ensuring that data access is restricted based on user roles.

1. As a department chair, I occasionally receive inquiries from potential employers seeking students with experience in a specific field, such as machine learning. In such cases, I need to run a query to generate a list of students who have completed machine learning courses. Additionally, I may want to filter the results to include only students who achieved a minimum grade in those courses.

2. Each year, program coordinators select outstanding seniors within their respective programs. To facilitate this process, I need to run a query that retrieves a list of senior students who meet a specified minimum GPA requirement for each major.

3. One metric used in faculty evaluations is grade distribution. As a department chair, I need to be able to determine an instructor's grade distribution for each class, each semester, or over a longer period of time. A faculty member should be able to see only their own grade distribution.

4. As a department chair or administrator, I need to access enrollment numbers at multiple levels:
   • Program-level enrollment across all programs in the department.
   • Course-level enrollment across all courses in the department.
   • Faculty-level enrollment, showing the number of students taught by each instructor.

5. As a department chair, I need to track the total credit hours generated by each instructor. This should include not only the list of courses taught but also the credit hours generated. For example, if an instructor teaches a 3-credit-hour course with 30 students enrolled, the total generated credit hours should be 90 for that course.

6. As a department chair or program coordinator, I need to determine the number of students who still need to take a specific course. This can help in deciding which classes need to be offered when creating the schedule of classes.

7. As a faculty member, I need access to class rosters for current and previously taught courses. The rosters should include a list of students, their majors, and the grades received. Additionally, the system should allow reporting on class-wide statistics, such as overall class GPA.
